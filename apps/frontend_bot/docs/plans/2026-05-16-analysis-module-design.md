# Analysis Module Design

## Goal

Добавить в `frontend_bot` отдельный модуль записи на разбор, который
обрабатывает вход по кнопке `Записаться на Разбор` и ведёт пользователя по двум
сценариям:

- публичный разбор
- приватный разбор

## Chosen Approach

Выбран отдельный `analysis_module`, а не расширение `menu_module` или
`products_module`.

Причины:

- сценарий имеет собственные тексты и callback-ветки
- flow должен оставаться изолированным от onboarding и навигации меню
- позже здесь будет удобно добавить отдельную логику кнопок `Форму заполнил`

## Structure

Модуль включает:

- `handlers.py` для message/callback-хендлеров
- `keyboards.py` для inline-кнопок и callback id
- `messages.py` и `messages.json` для пользовательских текстов
- `README.md` и `AGENTS.md` для локальной документации

## Flow

1. Пользователь нажимает `Записаться на Разбор`.
2. Бот отправляет вводное описание разбора и две inline-кнопки:
   `Публичный разбор` и `Приватный разбор`.
3. При выборе публичного формата бот отправляет описание и клавиатуру с:
   `Открыть анкету` и `форму заполнил(а)`.
4. При выборе приватного формата бот отправляет описание и клавиатуру с:
   `Открыть анкету` и `Форму заполнил`.
5. Callback-кнопки подтверждения анкеты пока завершаются только `callback.answer()`
   без бизнес-логики.

## Integration

- роутер модуля регистрируется явно в `app/bot/registry.py`
- существующая кнопка главного меню переиспользуется как вход в модуль
- текст кнопки выравнивается до `Записаться на Разбор`
